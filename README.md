# Todo AI

A to-do app that turns a written goal into a concrete task plan, then helps you manage it with a
board, notes, a Pomodoro timer and stats. Built with Next.js 16 (App Router), React 19,
TypeScript and Tailwind CSS v4.

## Features

### 1. AI task generation

Type a goal such as *"Organise a 500-person conference"* and get back 6–10 prioritised tasks with
suggested categories and staggered due dates.

- **With an API key**, plans are generated by Claude via `POST /api/generate`.
- **Without an API key**, a deterministic built-in planner picks one of eight templates (Product,
  Work, Study, Travel, Fitness, Moving, Event, Generic) by matching keywords in your goal.
- The badge under the button always tells you honestly which engine produced the plan.
- The route **never throws**. A missing key, a timeout, a non-2xx response or malformed model JSON
  all fall back to the local planner, so the deployed demo works with no configuration at all.

Generated plans are shown as a review list. Nothing is added to your board until you tick the tasks
you want — generation is never destructive.

### 2. Task board

- **List** and **Kanban** views (Kanban uses dropdown move buttons, no drag library).
- Create a task by hand, edit any field inline, and delete with a confirmation step.
- Priority, category and due-date chips, with overdue dates highlighted in red.
- Search across title, details and category; filter by status, priority and category.
- A completion progress bar across everything on the board.

### 3. Notes

- Split list/editor layout with pinned notes first.
- Create, rename, edit, pin, recolour, tag with a category, and delete with a confirmation.
- Full-text search across title, body and category.
- Autosave with a 500 ms debounce and a "Saved HH:MM" indicator.
- Seven colour swatches and a sort by recently updated, recently created or title.

### 4. Pomodoro focus timer

- 25 / 5 / 15 minute focus, short break and long break modes, with a long break every fourth
  completed focus session.
- The timer computes remaining time from an absolute `Date.now()` deadline on every tick, so it
  stays accurate when the browser throttles a background tab.
- Pick a task and "log a session" to increment its `focusSessions` counter and add to today's focus
  total.

### 5. Stats and categories

- Open, completed, completion rate, overdue, focus minutes today and in total.
- A 7-day completion bar chart rendered as plain SVG — no charting library.
- A category breakdown derived from both tasks and notes, including an "Uncategorized" bucket.

### Cross-cutting

- Everything persists to `localStorage` behind a hydration guard, so there is no server, no
  database and no login.
- Export and import a JSON backup from the header.
- Responsive layout, `prefers-color-scheme` dark mode, keyboard accessible controls, and a
  `prefers-reduced-motion` fallback.

## Getting started

Requires **Node.js 20.9 or newer** (pinned in `engines`).

```bash
npm install
npm run dev
```

Open <http://localhost:3000>.

| Script | What it does |
| --- | --- |
| `npm run dev` | Development server with hot reload |
| `npm run build` | Production build |
| `npm run start` | Serve the production build |
| `npm run lint` | ESLint (flat config, `eslint-config-next`) |
| `npm run typecheck` | `tsc --noEmit` |

### Optional: enable Claude

The app is fully functional without a key. To generate plans with Claude instead of the built-in
planner:

1. Copy `.env.example` to `.env.local`.
2. Set `ANTHROPIC_API_KEY` to a key from [console.anthropic.com](https://console.anthropic.com/settings/keys).

```bash
ANTHROPIC_API_KEY=sk-ant-...
```

`ANTHROPIC_MODEL` is optional and defaults to `claude-sonnet-5`.

The key is read only inside the route handler on the server and is never sent to the browser. The
API is called directly over `fetch`, so there is no SDK dependency.

## Project structure

```
app/
  layout.tsx                Root layout, fonts and metadata
  page.tsx                  Dashboard shell and tab routing
  globals.css               Tailwind v4 theme and light/dark tokens
  api/generate/route.ts     POST { goal } -> { tasks[], engine }
components/
  GeneratePanel.tsx         Goal input, engine badge, review list
  TaskBoard.tsx             List/kanban views, filters, search, progress
  TaskCard.tsx              One task, inline editing and status moves
  NotesPanel.tsx            Note list, search, sorting, selection
  NoteEditor.tsx            Debounced autosave editor
  FocusTimer.tsx            Pomodoro timer with absolute deadline
  StatsPanel.tsx            Stat cards, 7-day chart, category breakdown
  ui.tsx                    Button, Input, Textarea, Select, Badge, Card…
lib/
  types.ts                  Data model, constants and small validators
  factory.ts                Pure create/parse helpers, shared by client and server
  store.ts                  localStorage store, useSyncExternalStore hooks, CRUD
  planner.ts                Deterministic local template planner
  ai.ts                     Anthropic call, defensive JSON parsing and validation
```

`lib/factory.ts` is deliberately separate from `lib/store.ts`: the store is a client module with
React hooks, while the route handler needs the same pure factory functions on the server.

### How persistence works

`lib/store.ts` wraps `localStorage` in a small external store exposed through
`useSyncExternalStore`. The server snapshot is always the empty initial value, so React renders a
loading skeleton on the server and during hydration and then swaps in your saved data. That removes
the hydration mismatch you normally get from reading `localStorage` during render.

Every read is wrapped in `try/catch`, so corrupt or partial data falls back to the initial value
instead of breaking the app. Writes use per-store keys under the `todo-ai.*.v1` namespace.

## Deploying to Vercel

The repo is set up for the Vercel Next.js preset with **no environment variables**, because the
local planner needs no key.

1. Push this repository to GitHub.
2. Go to [vercel.com/new](https://vercel.com/new) and import the repository.
3. Accept the detected Next.js preset and deploy.
4. Add `ANTHROPIC_API_KEY` in Project Settings → Environment Variables *only if* you want Claude
   powered generation.

## Design decisions

- **No chart or drag-and-drop library.** The 7-day chart is inline SVG and the Kanban moves via
  dropdowns. Fewer dependencies means a faster build and a smaller supply chain for a demo app.
- **Hand-rolled UI primitives** in `components/ui.tsx` rather than a component library, so every
  colour is driven by the CSS custom properties in `globals.css` and dark mode is a single media
  query rather than a class toggled in JavaScript.
- **Tailwind v4 is CSS-first.** There is no `tailwind.config.js`; the theme is declared with
  `@theme inline` in `app/globals.css`.
- **The API route is total.** It has one exit path that always returns `{ tasks, engine }` with a
  200. This is what lets the public deployment work with no secrets configured.

## Limitations

- Data lives in one browser's `localStorage`. There are no accounts, no server database and no
  cross-device sync. Use Export for a backup.
- Clearing site data clears your tasks and notes.
- Planner templates are keyword-matched heuristics, not understanding — that is what Claude is for.

## Out of scope

Authentication, a server database, cross-device sync, unit tests beyond the type checker, and
custom domains.
